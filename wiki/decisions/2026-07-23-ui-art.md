# Authentic UI art from HEROES2.AGG

> The player chrome is real HOMM2 sprites extracted from the game archive, themed Good/Evil.

**Date:** 2026-07-23 **Status:** accepted

## Context

The Good/Evil skins were CSS approximations. Goal: use the real game art (frame, buttons) so it
looks like HOMM2, keep it responsive/mobile, and stay legally safe on a public deploy.

## Decision

- **Extraction** (build-time): `scripts/extract-art.ts` ports fheroes2's AGG + ICN + KB.PAL decode →
  transparent PNGs. Editorial `src/data/assets.ts` maps roles (`frame`, `btn`, `btn-pressed`) to
  `{icn,index,slice,trim}` per theme (Good = base ICN, Evil = `E`-suffixed). See [[asset-extraction]].
- **Serving**: PNGs gitignored under `public/art/ui/`, same-origin relative `url()` in static CSS;
  committed `art-manifest.json` + bijection test. No JS injector, no FOUC.
- **Card frame**: `SURDRBKG`/`SURDRBKE` via CSS `border-image` (`fill`). The baked drop-shadow (16px
  left+bottom) is **cropped in the extractor** (`trim`); a subtle CSS shadow is added to the card
  only; the viewport `.page-frame` has none. Per-theme `--frame-repeat`: **Good = `round`** (uniform
  stone tiles cleanly), **Evil = `stretch`** (its gem-studded border can't 9-slice/tile without
  fragmenting; stretch keeps the ornate corners + a continuous metal edge).
- **Page frame** (ornate viewport border, role `page`): `ADVBORD`/`ADVBORDE` (the adventure-map
  border) via `border-image … 40 round` on `.page-frame`. The full sprite is 640×480 and its right
  ~176px is the in-game control panel, not wood — so the extractor **crops to the map frame** with
  `trim.right: 160` (→ 480×480), leaving a clean 4-sided wood-and-gem border that tiles with `round`.
  Without the crop the right edge repeated panel fragments.
- **Buttons**: `SYSTEM`/`SYSTEME` released/pressed faces via `border-image` on the existing real
  `<button>`; dark glyphs (`--frame-edge`) on the beige/silver face.
- **Settings icon**: the game's real System-Options **computer** (`ADVBTNS.ICN` #14), lifted off its
  button face with `keyLuma` + tinted (role `settings`) — replaces the earlier hand-drawn glyph.
- **Theme toggle**: game **creature** icons (`MONS32.ICN`) — Good = **Black Dragon**
  (#37), Evil = **Phoenix** (#28) (role `creature`); shows the current theme's creature.
- **Text**: body + display titles are near-white (`--text` `#f2ede1`, both themes). Icon buttons and
  text buttons share the same **active** style (`filter: brightness(0.8)` darken, no pressed-sprite
  swap on toggle). Glyphs are sized larger inside the same-size buttons.
- **Cursor** (role `cursor`): the HOMM2 pointer `ADVMCO.ICN` #0, upscaled ×2, applied via a per-theme
  `--cursor` token (`cursor: url(...) 2 2, auto`) on `body` and the interactive elements, so the game
  pointer shows everywhere (like the reference site).
- **Transport/settings icons**: play/prev/next use the game's **own arrow sprite** (role `arrow` =
  `RECRUIT.ICN` up-arrow rotated to point right; CSS mirrors it for left; single = play, double =
  skip) per user request to "use game icons". Pause/shuffle/repeat/settings are blocky **pixel-art
  SVGs** (`src/ui/icons.tsx`, a 12×12 `#`-grid → one `<rect>` per horizontal run,
  `shapeRendering="crispEdges"`, tinted by `currentColor`). The whole transport row is dark brown
  `--control-ink` to match the tinted arrow sprite. Album/theme/volume icons stay smooth SVGs.
- **Theme tokens**: `[data-theme]` gains `--frame-src`, `--frame-repeat`, `--btn-face`,
  `--btn-face-pressed`. Amends [[2026-07-22-theming]] ("pure CSS re-skin" is superseded).
- **Scope chips + dialog Close**: the game's beige **buttons** via the `--btn-face` sprite
  (`border-image … stretch`, matching the transport buttons), centred `--chip-ink` labels; active
  scope = the same button darkened (`filter: brightness(0.8)`). (A pure-CSS variant was tried to
  perfect label centring but reverted — the user preferred the authentic sprite bevel.)
- **Progress bar**: a horizontal take on the game **scroll bar** — black recessed groove
  (`--groove-bg`) with a gold frame and a beige beveled grip (`--thumb-face`) sitting *inside* the
  groove; no time labels.
- **Text**: display text is a fixed gold `--font-gold` (`#dcc132`); transport glyphs + the tinted
  arrow are `--control-ink`. No forced uppercase (labels are Title-case).
- **Evil overrides**: buttons are grey iron (`--btn-*` greys), glyphs/labels + arrow tint are dark
  grey `#505050`, and the scroll-bar grip is grey (`--thumb-face`). Good is brown/beige.
- **Spacing**: inter-element spacing lives on `.game-frame__inner` (flex column, `--space-4` gap),
  shared by the player and the settings dialog (dialog children carry no own margins).
- **Layout**: responsive/fluid (not fixed-size); `image-rendering: pixelated` on sprite layers;
  mobile media query (thinner page frame, wrapping chips, ≥34px chip tap targets).

## Consequences

- Regenerating art needs a local game install (`HOMM2_DATA_DIR`) + `yarn extract:art`; a CI build
  can't produce it — production asset delivery is parked tech-debt (see [[audio-hosting]]).
- Evil's `stretch` slightly elongates its border metal; acceptable vs the fragmenting alternatives.
- Fonts: the faithful HOMM2 typeface is now **real** — a build-time pipeline renders the game's own
  bitmap glyphs (`FONT.ICN`/`SMALFONT.ICN`) into TTF webfonts. Supersedes the earlier "deferred /
  needs a web-licensed woff2" note. See [[homm2-font]]. Titles + chips render in the authentic font;
  the serif stack is now only a fallback.
