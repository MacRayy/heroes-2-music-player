# Theming: two-tier CSS custom properties on `[data-theme]`

> Good/Evil skins via semantic CSS variables remapped on `<html>[data-theme]`; set pre-paint.

**Date:** 2026-07-22 **Status:** accepted

## Context

Two full interface skins (Good = blue/gold, Evil = red/dark) must re-skin the whole player from
one toggle, persist across reloads, and avoid a flash of the wrong theme on load.

## Decision

- `src/theme/tokens.css` — structural tokens + the GOOD semantic palette under `:root` (default).
- `src/theme/themes.css` — `:root[data-theme='good']` (explicit) and `:root[data-theme='evil']`
  override the semantic vars (`--panel-top/bot`, `--btn-hi/mid/lo`, `--gold*`, `--accent`,
  `--text*`, `--bg-tint`).
- All component CSS reads **only semantic vars** — no hardcoded hex. Two-file split (structure vs
  palette) keeps the theme surface small.
- `src/theme/useTheme.ts` toggles `data-theme` on `<html>` and writes `localStorage['h2mp-theme']`.
- `index.html` has an inline pre-paint script that reads that key and sets `data-theme` **before
  first paint** → no theme flash.

## Consequences

- Adding a themeable color = add a semantic var in both theme blocks; never hardcode in components
  (enforced by convention + `solution-critic`).
- UI primitives (`GameButton`, `GameFrame`) are pure CSS recreations driven entirely by these vars,
  so they re-skin for free. **(Superseded 2026-07-23 by the authentic-art pass:** they now use
  extracted HOMM2 sprites via an asset-token tier — `--frame-src`/`--btn-face`/`--frame-repeat` —
  set per `[data-theme]`; frame via `border-image`, buttons via `background`/`border-image`. See
  [[asset-extraction]].)
- The storage key `h2mp-theme` is shared between the pre-paint script and `useTheme` — keep them in
  sync if renamed.
